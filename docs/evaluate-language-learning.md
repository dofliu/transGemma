# TranslateGemma 導入語言學習功能評估報告

## 一、現有架構盤點

| 組件 | 說明 | 語言學習可複用性 |
|------|------|------------------|
| **Ollama LLM 推論** | 透過 TranslateGemma 模型翻譯 | 高 — 可用於解釋文法、產生例句、批改寫作 |
| **STT (faster-whisper)** | 語音辨識 | 高 — 可做發音練習、聽寫測驗 |
| **TTS (edge-tts)** | 17 語言神經語音合成 | 高 — 可做範讀、跟讀對比 |
| **OCR (Tesseract)** | 圖片文字辨識 | 中 — 可辨識學習素材（課本截圖等） |
| **55+ 語言支援** | languages.py 完整語言元資料 | 高 — 涵蓋主流學習目標語言 |
| **Gradio UI** | 分頁式互動介面 | 高 — 直接新增 Tab 即可擴充 |
| **歷史紀錄 (SQLite)** | 紀錄翻譯任務 | 中 — 可擴展為學習進度追蹤 |
| **串流輸出** | 翻譯結果即時串流 | 高 — 互動式教學體驗 |
| **術語表 / 風格指南** | 自訂翻譯規則 | 中 — 可轉為學習重點詞彙表 |

**結論：現有架構約 70% 的元件可直接或稍加改造用於語言學習場景。**

## 二、可行的語言學習功能方案

### 方案 A：翻譯輔助學習（低成本，1-2 週）

在現有翻譯流程中加入「學習模式」，翻譯結果附帶教學資訊：

```
使用者輸入: "The meeting has been postponed until further notice."
```

**一般模式（現有）：**
> 會議已延期，另行通知。

**學習模式（新增）：**
> **翻譯：** 會議已延期，另行通知。
>
> **重點詞彙：**
> - postponed (v.) 延期 — 例：The game was postponed due to rain.
> - until further notice (phr.) 直到另行通知
>
> **文法解析：**
> - "has been postponed" → 現在完成式被動語態 (Present Perfect Passive)
>
> **相似表達：**
> - The meeting has been rescheduled. (會議已重新安排)
> - The meeting is on hold. (會議暫停)

**實作方式：** 修改 `translator.py` 的 `_build_prompt()`，在學習模式下使用不同 prompt 模板，要求 LLM 同時輸出翻譯 + 詞彙 + 文法解析。

### 方案 B：互動式語言練習（中成本，3-4 週）

新增獨立分頁，利用現有 STT + TTS + LLM 建構練習環境：

| 練習模式 | 使用的現有元件 | 新增內容 |
|----------|----------------|----------|
| **單字閃卡** | LLM 產生例句 + TTS 發音 | 閃卡 UI、Spaced Repetition 排程 |
| **聽寫測驗** | TTS 播放 + STT 聽寫比對 | 評分邏輯、難度分級 |
| **發音練習** | STT 辨識使用者 + TTS 範讀 | 發音比對、音調視覺化 |
| **情境對話** | LLM 模擬角色對話 + TTS | 對話流程管理、場景庫 |
| **寫作批改** | LLM 文法檢查與潤飾 | 錯誤分類、建議 UI |

### 方案 C：完整語言學習平台（高成本，6-8 週）

在方案 B 基礎上加入：
- 使用者帳號與學習進度系統
- 課程結構（初/中/高級、主題式）
- 學習數據分析儀表板
- 多媒體素材庫（影片片段搭配字幕學習）
- 社群功能（學習夥伴配對）

## 三、技術可行性分析

### 可直接利用的部分

1. **Prompt Engineering（零成本）**
   - 現有 `_build_prompt()` 架構已支援自訂 prompt
   - 只需新增語言學習專用 prompt 模板
   - LLM 本身就擅長文法解釋、例句生成

2. **STT + TTS 管線（已就緒）**
   - `speech_to_text()` 可做聽寫 / 發音評估的輸入
   - `text_to_speech()` 可做範讀播放
   - 即時串流語音管線可支持即時口語練習

3. **Gradio UI 擴展（低成本）**
   - 新增 `TabItem("語言學習")` 即可
   - 現有 UI 模式（輸入 → 串流輸出）直接適用

### 需要額外開發的部分

1. **學習進度追蹤**
   - 現有 `history.py` 的 SQLite 結構需擴展
   - 新增：學習記錄表、詞彙掌握度、練習成績
   - 估計工作量：1-2 天

2. **Spaced Repetition 演算法**
   - SM-2 或 FSRS 演算法實作
   - 用於閃卡複習排程
   - 估計工作量：1 天（有成熟的 Python 套件可用）

3. **發音評估**
   - faster-whisper 的辨識結果可做基礎比對
   - 進階音素級比對需要額外工具（如 Kaldi / Wav2Vec2）
   - 基礎版 1 天，進階版 1-2 週

4. **教學素材管理**
   - 課程 / 練習題庫的資料結構
   - 可利用 LLM 動態生成，減少手動維護
   - 估計工作量：2-3 天

### 潛在風險

| 風險 | 等級 | 緩解方式 |
|------|------|----------|
| LLM 文法解釋偶有錯誤 | 中 | 限定範圍、加上 disclaimer |
| 發音評估精度不足 | 中 | 先做基礎版（文字比對），後續升級 |
| STT 對學習者口音辨識差 | 低-中 | 提供多次重試、降低嚴格度 |
| 效能瓶頸（本地推論） | 低 | 學習功能多為短句，推論快 |
| 功能範疇過大 | 高 | 採分階段交付（A → B → C） |

## 四、建議路線圖

```
Phase 1（1-2 週）: 翻譯學習模式
├── 在翻譯結果中加入詞彙/文法/例句解析
├── 新增「學習模式」開關
└── 擴展 eval dataset 加入學習品質評估

Phase 2（3-4 週）: 互動練習模組
├── 單字閃卡 + Spaced Repetition
├── 聽寫測驗（TTS → 使用者輸入 → 比對）
├── 發音練習（TTS 範讀 + STT 回饋）
└── 學習進度儀表板

Phase 3（選擇性）: 進階功能
├── AI 情境對話
├── 寫作批改
├── 影片字幕學習（利用現有影片翻譯管線）
└── 學習分析報表
```

## 五、結論與建議

**TranslateGemma 非常適合導入語言學習功能。** 理由：

1. **技術基礎完整**：LLM、STT、TTS、多語言支援全部到位，這正是語言學習工具的核心技術棧
2. **架構可擴展**：模組化設計 + Gradio 分頁 UI，新增功能的摩擦力極低
3. **差異化優勢**：本地優先（隱私）+ 多模態（文字/語音/影片）是市面語言學習工具少見的組合
4. **低風險起步**：Phase 1 只需修改 prompt 模板，幾乎零架構變動

**建議從 Phase 1 開始**，在現有翻譯流程中加入學習模式，以最小成本驗證需求與使用者回饋，再決定是否推進 Phase 2。
